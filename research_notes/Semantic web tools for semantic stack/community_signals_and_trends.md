# Community signals and trends: semantic web / knowledge graph practitioner recommendations, releases and discussion, 2025-2026

Scope note: this file covers community and industry *signals* (who is recommending/announcing what, where, when) as input for choosing additions to the MetaCoding `semantic-stack` Docker Compose stack. Tools already in the stack (QLever, Fuseki, Oxigraph, RDF4J Workbench, OntoRefine, OpenRefine, RML Mapper, WebVOWL, Trifid, Blueprint, YASGUI, Comunica, rdflib-orm, surfrdf) are only mentioned where a signal about them is itself informative. Deep tool-by-tool evaluation is left to other researchers. Research date: 14 October 2026.

## Key question 1: What are named practitioners posting on LinkedIn / their blogs and newsletters about tool choices in 2025-2026?

### Takeaway
LinkedIn itself is effectively unsearchable via web search (every `site:linkedin.com` query returned non-LinkedIn pages), so practitioner signal had to be recovered from blogs, newsletters and GitHub orgs owned by the named people. ### Inferences
- The practitioner conversation in 2025-2026 is dominated by LLM+KG topics (agents, GraphRAG, ontology-driven AI), not by new triplestores; the tool signals that do surface from this group are *front-ends and validators* (SHACL Dashboard, Sparnatural, Miravi, Vault-LD) rather than back-ends.
- QLever's standing has clearly risen among practitioners (Sequeda's "DuckDB for RDF" remark; Wikidata/UniProt adoption in KQ4), which validates the stack's choice of QLever as primary.
- Bob DuCharme's move to Graphwise and Sequeda's move to ServiceNow mean two of the most-read semweb voices now write from vendor/enterprise positions; treat their tool commentary accordingly.

### Inferences
- The conference demo/resource tracks of 2025 point to three self-hostable categories the stack lacks: (a) SHACL *reporting/dashboarding* (SHACL Dashboard, Shacl4Bib, RDF Differ), (b) library-world ETL/vocabulary tools with Docker images (Metafacture, Skosmos, Annif), and (c) low-code Linked Data application platforms (LinkedDataHub, which is already Docker-Compose-native and uses Fuseki).
- Jelly's SEMDEV presentation plus its JVM/Python implementations make it the most "conference-validated" new serialization; it is a library/format rather than a container, so it would enter a stack via Jena/RDF4J plugins rather than a service.

## Key question 3: GitHub trends, notable new repos, and which awesome-lists are best curated (and what they list that the stack lacks)

### Takeaway
GitHub search (14 Oct 2026) shows a wave of new Rust/Go RDF engines (OxiRS, PurRDF, Oxilite, goRDFlib, duck_rdf, Tentris relaunch, Grafeo), browser-based editors (OntoSphere, OrionBelt Ontology Builder, Intentional Arrangement SKOS), and agent/LLM-flavoured KG tools (open-ontologies at 1,054 stars, cortexdb, OntoCast, ontobricks). The best-maintained awesome-lists are `ozekik/awesome-ontology` (pushed 12 Oct 2026, 719 stars) and `semantalytics/awesome-semantic-web`; across them the stack is missing a SHACL form/report UI, a SPARQL formatter, an RDF diff tool, a vocabulary/SKOS server (Skosmos/VocBench), an ontology documentation generator (WIDOCO/pyLODE), and a rule/reasoning engine (Nemo, EYE, OWL-RL).

## Key question 4: Standards activity (RDF 1.2 / SPARQL 1.2 / RDF-star, SHACL 1.2, RDF canonicalization, JSON-LD, Solid) and which tools support it

### Takeaway
RDF 1.2 Concepts and Semantics reached Candidate Recommendation on 7 April 2026; SPARQL 1.2 Query was still a Working Draft (23 Jan 2026) and SHACL 1.2 Core was still a Working Draft as of 28 Aug 2026. Oxigraph (behind an `rdf-12` feature flag, with RDFC-1.0 canonicalization and JSON-LD 1.1 default since Feb 2025), Jena 5.4+/6.x (experimental RDF 1.2), and new Rust engines (PurRDF "RDF 1.2 engine", OxiRS "SPARQL 1.2") are the implementations signalling 1.2 support; Solid's W3C work continues under the Linked Web Storage WG with Community Solid Server at v7.2.0 (Jul 2026) and v8 alphas.
